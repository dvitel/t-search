# Configurations

The purpose of different configuration files in this folder is to test the aspects of evolutionary pipeline implemented in the t-search Symbolic Regression (SR) solver.

The file **_full.json** serves as the template of all possible options and provides the examples for the values.

## Core parameters 

The following list presents the parameters and their possible values. 
Some values are hardcoded as defaults, therefore you may want to import GPSolver directly to your app 
when custom settings, like operations, fitness etc are required.

- `ops` - set of allowed symbols, their operational semantics are hardcoded in the **solver.py** and **_full.json** demonstrates all of them. 

- `fitness_name` - defines the fitness and the loss for numerical optimizations. Supported: "nmse", "mse", "l1".

- `ops_counts` - (min, max) number of times the specified operation may occur in the formula. Default: (0, 100). 

- `forbid_patterns` - lisp expr for patterns that should be prohibited in terms that are generated by operators. 
Solver supports non-linear unification, any uppercase leaf (e.g. X, Y,...) iss treated as meta-variable for binding.
For instance, `(add X X)` would match any term with "add" operation at root with two equal children. 
Special meta-leaf "." (check **_full.json**) matches any subexpression at place. 
Meta-function "..." means "find anywhere in the tree". 
For instance, `(sin (... (sin .)))` would match all terms that has "sin" at root and another "sin" anywhere in its child. 

- `inner_ops_max_counts` - context-dependent count constraining. For an operation A, it specifies how many times an operator B may appear anywhere in its subtree.

- `immediate_arg_limits` - count constraints for immediate children only. For instance, `(inv (inv x))` reduces to 
`x`, therefore we may specify that under "inv" there should be zero immediate "inv" operators. 

- `prohibit_ops_on_consts_only` - if true, solver would avoid generating terms that contain operations only on constants.

- `max_term_depth` - depth constraint. Default: 17 

- `min_consts` and `max_consts` - count constraints of constants. Default: (0, 10)

- `min_vars` and `max_vars` - count constraints of free variables. Default: (1, 10)

- `max_gen`, `max_root_evals`, `max_evals` - define time limits for search. Default: search is limited by 100 population-based generations, 100K exaluations at term root, or 1M total evaluations including subexpressions.
Exit happens when whatever metric exceeds the limit first, or best term (with fitness < `fitness_atol`) is found.
Note that the solver caches the evaluations in the memory, therefore, only unique terms are counted.

- `with_inner_evals` - if true, computes fitness for inner terms also, otherwise only outputs are computed and inner terms are not used in the search. It exists for backward compatibility with old methods which did not consider fitness estimation of inner terms. Default: true

**NOTE**: for simple constrainting, using `inner_ops_max_counts` and `immediate_arg_limits` is more preferable than `forbid_patterns` as they provider prior validation of a term during random generation (therefore less computationally heavy), while full pattern matching is posterior constraint check, that discards invalid terms. 

## Basic Koza configurations 

- **koza-base-set1.json** - unconstrained GP, set1 operations with binary "sub" and "div"
- **koza-base-set2.json** - unconstrained GP, set2 operations with unary "neg" and "inv"
